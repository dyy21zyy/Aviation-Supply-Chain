# aviation_sideinfo_case

## 1) Project title
**Event-based Bayesian side-information numerical illustration** for the case:
**2025 Antwerp-Bruges harbour pilots industrial action and aviation engine-component supply disruption risk**.

## 2) Research purpose
This repository provides a small, reproducible Python workflow showing how event-based side-information can:
1. update disruption-risk beliefs using Bayes' rule, and
2. convert those beliefs into cost-sensitive resilience decisions.

## 3) Important disclaimer
This is an **event-based numerical illustration**, not a full empirical validation.

- Signal values are **manually coded illustrative variables** motivated by publicly reported event evidence.
- The project does **not** use proprietary aviation shipment data.
- The project does **not** scrape websites.
- The project does **not** call APIs.

## 4) Data description
Generated by `src/01_construct_case_data.py`:

- `data/antwerp_case_signals.csv`: event timeline plus coded signals.
  - `S1_industrial_action`: ordinal (0,1,2).
  - `S2_congestion_index`: a **constructed scaled congestion proxy** (0-100), not an official port index.
  - `S3_logistics_advisory`: binary (0/1).
- `data/likelihood_assumptions.csv`: categorical likelihood assumptions for `S1` and `S3`.
- `data/cost_scenarios.csv`: cost and action-effectiveness scenarios for decisions.

## 5) Method
- Prior disruption probability: `Beta(2,18)`.
- Categorical likelihoods for `S1` and `S3`.
- Beta likelihood for scaled congestion proxy `S2/100`:
  - given disruption: `Beta(6,2)`
  - given no disruption: `Beta(2,6)`
- Bayes rule for posterior risk.
- Optional dependence-adjusted posterior (illustrative correction only, not an estimated Gaussian copula).
- Cost-sensitive decision threshold:
  - `tau = C_A / (e * C_D)`

## 6) How to run
From this folder (`aviation_sideinfo_case/`):

```bash
python src/01_construct_case_data.py
python src/02_bayesian_update.py
python src/03_decision_threshold.py
python src/04_sensitivity_analysis.py
```

## 8) Interpretation notes for journal use
This project is designed for transparent methodological illustration:
- It links publicly discussed event evidence to manually coded side-information.
- It demonstrates posterior updating and decision threshold logic in a replicable pipeline.
- It supports narrative discussion of when action would be triggered under different cost assumptions.

## 9) Limitations
- single event
- manually coded signals
- no estimated copula
- no XGBoost benchmark
- no claim of causal identification
- full validation would require a multi-event panel dataset

## Public-event motivation (context only)
The coding is motivated by public reports around the 2025 Antwerp-Bruges harbour pilots industrial action: port throughput reportedly falling from typical ~60-80 vessels/day to 31 on an affected day, reports of delayed/stranded/diverted vessels, Maersk advisories affecting Antwerp and Zeebrugge traffic, later reports of 188 vessels waiting with operations near ~70% capacity, and Inchcape Shipping Services reports of 210 waiting vessels (including 70 waiting to depart Antwerp and 133 in the North Sea). These details motivate signal design only; this repository does not claim they are raw machine-ingested measurements.
